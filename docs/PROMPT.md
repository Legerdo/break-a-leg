# 원본 프롬프트

이 게임을 만들 때 사용한 최초 요청문 원문이다(수정 없이 보관).

---

# Claude Opus 5.5 — Troll Pixel Platformer Level Design Benchmark

사용 가능한 개발 도구를 활용하여 **짧지만 완성도 높은 2D 픽셀 아트 플랫포머 게임을 실제로 제작하라.**

이번 작업의 핵심 평가 대상은 코드 작성량이나 그래픽 자산 수가 아니다.

**플레이어의 예측을 읽고, 규칙을 학습시키고, 그 학습된 규칙을 영리하게 뒤집는 수제 레벨 디자인 능력**을 보여주는 것이 최우선 목표다.

`Level Devil`, 고양이 마리오류의 “낚시 플랫포머”에서 영감을 받을 수 있지만 기존 게임의 레벨, 캐릭터, 그래픽, 함정을 복제하지 말고 독창적인 게임으로 만들어라.

---

## 1. 목표

브라우저에서 즉시 플레이할 수 있는 완결된 픽셀 아트 플랫포머를 만든다.

목표 플레이 시간:

- 첫 플레이: 약 10~20분
- 숙련 후 클리어: 약 3~6분

게임은 단순해야 한다.

플레이어가 알아야 할 기본 조작은 가능한 한 다음 정도로 제한한다.

- 좌우 이동
- 점프
- 재시작

복잡한 전투, 인벤토리, 스킬 트리, 대화 시스템은 넣지 않는다.

복잡성은 조작법이 아니라 **레벨과 상황의 변화**에서 만들어라.

---

# 2. 핵심 디자인 철학

이 게임은 플레이어를 죽이는 게임이 아니다.

**플레이어가 다음 상황을 예측하게 만든 뒤 그 예측을 이용하는 게임**이다.

좋은 낚시는 다음 흐름을 가진다.

`관찰 → 예상 → 행동 → 배신 → 즉시 이해 → 재도전 → 극복`

죽은 직후 플레이어가

> "아 씨발, 그래서 그랬구나."

라고 이해할 수 있어야 한다.

반대로

> "내가 왜 죽은 거지?"

가 반복된다면 실패한 레벨 디자인이다.

---

# 3. 절대 랜덤 데스맵으로 만들지 마라

다음 같은 설계에 의존하지 않는다.

- 아무 단서 없이 화면 밖에서 즉사체가 날아옴
- 모든 바닥에서 무작위로 가시가 솟음
- 점프할 때마다 무작위 결과 발생
- 암기하지 않으면 절대로 대응할 수 없는 장거리 함정
- 픽셀 단위 정밀 점프
- 의미 없는 가짜 발판 반복
- 같은 함정을 색만 바꿔 계속 사용
- 죽는 이유를 알아볼 수 없는 함정
- 긴 구간을 통과한 뒤 마지막에 갑자기 즉사시키고 처음부터 다시 시작

**불공평해 보여도 실제로는 학습 가능하고 재현 가능해야 한다.**

랜덤성보다는 의도적으로 설계된 패턴을 우선한다.

---

# 4. 레벨 디자인의 핵심 구조

처음부터 끝까지 하나의 수제 레벨 또는 자연스럽게 이어지는 소수의 스테이지로 구성하라.

각 구간에는 역할이 있어야 한다.

### 1단계 — 신뢰 구축

일반적인 플랫포머처럼 행동한다.

플레이어에게 다음을 학습시킨다.

- 블록은 밟을 수 있다.
- 가시는 위험하다.
- 문은 목적지다.
- 체크포인트는 안전하다.
- 적은 일정한 방식으로 움직인다.
- 화면에 보이는 공간이 실제 이동 공간이다.

처음부터 계속 낚으면 플레이어에게 예측 모델 자체가 생기지 않는다.

먼저 규칙을 믿게 만들어라.

---

### 2단계 — 단일 규칙 배신

익숙한 규칙 하나씩만 뒤집는다.

예:

- 안전해 보이는 바닥이 밟으면 내려감
- 가시를 넘으려 점프하면 천장에서 위험물이 내려옴
- 도착 직전 목표물이 조금 이동함
- 평범한 블록이 플레이어 접근 시 움직임
- 체크포인트처럼 보이는 물체가 다른 기능을 가짐
- 이전까지 안전했던 공간이 조건에 따라 변함

단, 실제 함정은 직접 새롭게 설계하라.

위 예시를 그대로 체크리스트처럼 복제하지 마라.

---

### 3단계 — 패턴 학습

같은 계열의 함정을 약간 변화시키면서 플레이어에게 새로운 규칙을 학습시킨다.

플레이어가

> "아, 이제 이 게임이 무슨 짓 하는지 알겠네."

라고 생각하게 만든다.

여기가 중요하다.

**플레이어에게 자신감을 줘야 다음 배신이 먹힌다.**

---

### 4단계 — 역낚시

플레이어가 앞서 배운 낚시 자체를 예상하기 시작하면 그 예상을 이용한다.

예를 들어:

- 이전에는 항상 안전지대가 함정이었다면 이번에는 진짜 안전함
- 함정일 것 같은 물체를 피했더니 피한 경로가 위험함
- 움직일 것으로 예상한 플랫폼이 움직이지 않음
- 이전 규칙대로 행동하면 실패하고 처음 배운 기본 행동이 정답

단순한 반전이 아니라 **플레이어가 형성한 메타 규칙을 대상으로 설계**하라.

---

### 5단계 — 복합 함정

이미 학습한 2~3개의 규칙을 짧은 하나의 상황 안에서 결합한다.

한 번에 새로운 규칙을 여러 개 추가하지 마라.

플레이어는 무엇이 잘못됐는지 이해할 수 있어야 한다.

---

### 6단계 — 피날레

최종 구간은 지금까지 학습한 내용을 시험한다.

새로운 즉사 기믹을 무더기로 넣는 대신 기존 규칙을 재조합한다.

마지막에는 한 번 더 기억에 남을 만한 반전을 넣어도 좋다.

하지만 단순히

`FINISH → 갑자기 사망`

같은 싸구려 반전으로 끝내지 마라.

클리어 순간에는 실제 성취감을 줘라.

---

# 5. 낚시 설계 규칙

전체 게임에 최소 **12개 이상의 서로 구별되는 낚시 상황**을 직접 설계하라.

하지만 12개의 독립된 장난을 늘어놓지 말고 서로 관계를 가지게 한다.

좋은 함정은 다음 중 하나 이상을 이용한다.

- 플레이어의 이동 습관
- 플랫포머 장르 관습
- 화면 구성
- 시선 유도
- 반복으로 형성된 기대
- 안전지대에 대한 기대
- 목표 지점에 대한 기대
- 타이밍 예측
- 이전 함정에서 얻은 학습
- UI 또는 환경에 대한 신뢰
- 카메라 움직임
- 공간 자체의 변화

**죽이기 위해 함정을 배치하지 말고 예상하게 만든 뒤 예상 때문에 죽게 만들어라.**

---

# 6. 공정성

낚시 게임이라고 물리적으로 개판이어도 되는 게 아니다.

기본 이동감은 매우 좋아야 한다.

반드시 구현하라.

- 안정적인 지상 이동
- 적절한 가속/감속
- variable jump height
- coyote time
- jump buffering
- 명확한 충돌
- 예측 가능한 점프 궤적
- 빠른 사망 판정
- 빠른 리스폰

캐릭터가 조작 때문에 죽는 것과 함정에 속아 죽는 것을 명확하게 분리할 수 있어야 한다.

---

# 7. 재도전 UX

낚시 게임에서 죽음은 진행 과정이다.

따라서 죽음의 비용을 최소화한다.

사망 후:

1. 짧고 명확한 사망 효과
2. 필요하다면 함정을 0.2~0.5초 정도 보여줌
3. 즉시 재시작

목표:

**사망 → 다시 조작 가능 상태까지 약 1초 내외**

긴 페이드, 메뉴 이동, 로딩 화면은 넣지 않는다.

R 키 또는 적절한 입력으로 즉시 수동 재시작도 가능하게 하라.

---

# 8. 체크포인트

체크포인트를 적절하게 사용한다.

낚시 하나를 파악하기 위해 이미 해결한 30초 구간을 반복하게 만들지 않는다.

다만 함정 바로 앞마다 체크포인트를 배치해서 긴장감을 없애지도 마라.

기준은:

**하나의 의미 있는 학습 단위가 끝났을 때 체크포인트를 제공한다.**

체크포인트 자체를 이용한 낚시도 가능하지만 남용하지 않는다.

---

# 9. 심리전

레벨의 시각 구성 자체를 게임 플레이에 사용한다.

예를 들어 플레이어의 시선을 한쪽으로 유도하면서 다른 곳에서 변화가 발생하게 할 수 있다.

다음을 활용할 수 있다.

- 빈 공간
- 조명
- 색 대비
- 움직이는 요소
- 아이템
- 문
- 표지판
- 좁아지는 통로
- 높은 플랫폼
- 카메라 프레이밍

하지만 시각 정보를 일부러 읽을 수 없게 만드는 방식은 쓰지 않는다.

**좋은 낚시는 정보를 감추는 것이 아니라 정보를 오해하게 만드는 것이다.**

---

# 10. 반복과 변주

한 기믹을 한 번만 쓰고 버리지 않아도 된다.

오히려 좋은 레벨 디자인이라면

`소개 → 확인 → 변형 → 역이용`

과정을 거친다.

예:

A라는 기믹을 안전한 상황에서 소개하고  
→ 실제 위협으로 사용하고  
→ 플레이어가 예상하게 만든 뒤  
→ 그 예상 자체를 함정으로 사용한다.

이런 식의 **기믹 문법**을 여러 개 만들어라.

---

# 11. 시각 스타일

명확하게 읽히는 고품질 픽셀 아트 스타일을 사용한다.

권장 방향:

- 제한된 색상 팔레트
- 강한 실루엣
- 작은 캐릭터
- 명확한 발판 경계
- 위험물의 좋은 가독성
- 짧고 선명한 애니메이션
- 픽셀 퍼펙트 렌더링
- nearest-neighbor scaling
- 화면 크기에 따른 정수배 확대
- `imageSmoothingEnabled = false`

아트 스타일은 직접 결정하라.

단순한 개발자용 사각형과 기본 도형으로 끝내지 마라.

외부 이미지가 없어도 직접 만든 픽셀 스프라이트, 타일, 배경, 파티클 등을 사용해 **실제 출시 가능한 작은 게임처럼** 보여야 한다.

---

# 12. 게임 필과 쥬스

장르 특성상 그래픽보다 레벨 디자인이 우선이지만 피드백은 충분히 넣는다.

필요한 곳에 다음을 활용하라.

- squash & stretch
- landing compression
- anticipation
- 짧은 화면 흔들림
- hit-stop에 준하는 짧은 정지
- 파티클
- 먼지
- 위험 요소 활성화 애니메이션
- 사망 효과
- 체크포인트 활성화
- 카메라 easing
- subtle parallax
- 짧은 UI 팝업

강도를 상황별로 조절한다.

계속 화면을 흔들거나 파티클을 뿌려서 가독성을 망치지 마라.

---

# 13. 유머

게임은 약간 악의적이어도 되지만 플레이어를 조롱하기보다 **게임 자체가 장난을 치는 느낌**이어야 한다.

짧은 표지판이나 UI 메시지를 사용할 수 있다.

텍스트에만 의존하지 않는다.

재미의 핵심은 상황 자체여야 한다.

밈이나 유행어를 남발하지 말고 게임 자체의 개성을 만들어라.

---

# 14. 기술

브라우저에서 실행되는 게임으로 만든다.

권장:

- TypeScript
- Vite
- Phaser 또는 직접 구현한 Canvas 2D 기반 구조

기존 프로젝트가 없다면 유지보수하기 쉬운 최소 프로젝트를 구성하라.

프레임레이트와 물리 동작은 가능한 한 분리하고 일반적인 데스크톱 환경에서 안정적인 60 FPS를 목표로 한다.

키보드 기본 조작:

- A/D 또는 ←/→: 이동
- Space / W / ↑: 점프
- R: 즉시 재시작
- Esc: 메뉴 또는 일시정지

필요하면 게임패드를 추가할 수 있다.

---

# 15. 레벨을 데이터로 설계하라

가능하면 레벨 구조와 함정을 코드 여기저기에 하드코딩하지 말고 데이터 중심으로 구성한다.

각 기믹은 재사용 가능한 형태로 만든다.

예:

- Trigger
- Hazard
- MovingPlatform
- CollapsingTile
- DynamicObstacle
- Checkpoint
- Goal
- CameraTrigger

단, 범용 엔진 제작이 목적은 아니다.

게임 하나를 완성하는 데 필요한 만큼만 추상화하라.

---

# 16. 직접 플레이테스트하라

구현 완료를 성공으로 간주하지 않는다.

실행해서 실제 플레이 흐름을 확인하라.

가능한 개발 도구와 브라우저 자동화/화면 캡처 기능을 적극적으로 사용한다.

특히 다음을 확인한다.

### 물리

- 점프가 일관적인가
- 발판 모서리 충돌이 이상하지 않은가
- 벽 또는 천장에 끼이지 않는가
- 움직이는 플랫폼과 충돌이 안정적인가

### 레벨

- 모든 구간이 실제로 클리어 가능한가
- 의도하지 않은 스킵이 가능한가
- 함정 하나가 지나치게 어렵지 않은가
- 실패 이유를 이해할 수 있는가
- 플레이어의 예측을 실제로 이용하고 있는가
- 똑같은 낚시를 반복하고 있지 않은가

### 템포

- 초반이 너무 느리지 않은가
- 낚시가 너무 촘촘하지 않은가
- 긴장과 휴식 구간이 존재하는가
- 체크포인트 간격이 적절한가
- 후반으로 갈수록 사고 과정이 발전하는가

---

# 17. 레벨 디자인 자체를 리뷰하라

게임을 완성한 뒤 각 주요 낚시 상황을 내부적으로 다음 기준으로 평가하라.

1. 플레이어는 무엇을 예상하는가?
2. 왜 그렇게 예상하는가?
3. 게임은 어떻게 그 기대를 뒤집는가?
4. 실패 직후 원인을 이해할 수 있는가?
5. 두 번째 시도에서는 실력 또는 지식으로 통과할 수 있는가?
6. 이전에 배운 내용을 이용하는가?
7. 이후 다른 함정을 위한 학습으로 연결되는가?

여기에 명확하게 답할 수 없는 함정은 수정하거나 제거한다.

# 18. 난이도 곡선

목표는 계속 어려워지는 점프 기술이 아니다.

**플레이어에게 요구하는 추론의 깊이가 증가해야 한다.**

초반:

`보이는 것에 반응`

중반:

`이전 패턴을 기억`

후반:

`게임이 내가 무엇을 예상하는지 예상한다는 사실까지 고려`

즉 마지막에는 플레이어와 레벨 디자이너가 서로 수를 읽는 느낌이 나야 한다.

# 20. 자율성

세부 아트 스타일, 세계관, 캐릭터, 색상, 함정 테마, 스테이지 구성, 연출은 스스로 결정하라.

명세를 문자 그대로 체크리스트처럼 구현하기보다 전체 목표를 이해하고 더 좋은 아이디어가 있으면 적극적으로 선택하라.

특히 함정 설계는 위의 예시를 복사하지 말고 자체적으로 고안한다.

결정을 내려야 할 때 우선순위는:

1. 레벨 디자인
2. 플레이 감각
3. 가독성
4. 재미있는 배신
5. 빠른 재도전
6. 시각적 완성도
7. 시스템 확장성

이다.
